# 优化日志

记录时间：2026-05-21

## 这次在处理什么

一开始 Vivado 报的是 `WNS` 和 `TNS` 不够。

简单说就是：

- `WNS < 0`：最慢的那条路来不及
- `TNS < 0`：不止一条路有问题
- 目标：`WNS > 0`，`TNS = 0`

这通常表示同一拍里做的事情太多了，需要拆一拆。

## 我这次的处理方法

核心思路就一个：

不要让很多判断和计算都挤在同一拍里。

我主要做了这些事：

1. 先把容易变动的输入同步一下，再统一取样。
2. 把一些经常重复用到的结果先存起来。
3. 把比较长的判断拆开，让后面的逻辑少走几步。
4. 对显示相关路径加上更符合实际的时序说明。

## slot4 这边做了什么

slot4 主要是把输入和状态整理得更稳一点。

- 按键和开关先同步，再按帧处理
- 门是不是开了、角色是不是落地、有没有过关或失败，这些结果先记住
- 不需要发声的时候，蜂鸣器直接保持静音
- 没被选中的时候，灯和数码管都回到干净的默认状态

这样做的好处是：

- 逻辑更直
- 画面和状态更稳
- 后面更不容易把时序拉长

## 其他地方也顺手整理了

项目里比较长的路径，不只一处。

所以我也把 slot3 和坦克里一些容易连成长链的地方顺了一下，让它们少做一些“这一拍必须全算完”的事情。

现在最慢的路径已经不在 slot4，而是在 slot3 的地图生成那边。

## 结果

最新后路由结果：

- `WNS = 0.140 ns`
- `TNS = 0.000 ns`
- `Failing Endpoints = 0`

bitstream 也已经生成成功：

- `build/vivado/game_console_top.bit`

## 现在的结论

当前工程已经能过 `100 MHz` 时序。

slot4 也已经并入项目，整体表现比之前更稳。

如果后面还想继续加余量，下一步最值得盯的是 slot3 的地图生成那条长路径。

## slot2 并入和优化

这次把 `slot2` 文件夹里的游戏并入到了工程里。

slot2 不是只放进来就结束，我也跑了 Vivado 检查。刚放进去之后，问题比较明显：

- 游戏能生成 bitstream
- 但是时序不达标
- 最差的时候 `WNS` 到了 `-23.994 ns`

也就是说，代码能编过，但跑在 100MHz 时钟下不够稳。

## slot2 主要问题

slot2 是一个俄罗斯方块游戏。

原来的写法里，有几件事挤在同一拍里做：

- 一次算出方块能掉到哪里
- 一次检查很多格子有没有碰撞
- 一次判断 20 行里哪些行满了
- 一次把棋盘重新整理好
- 七段数码管也在一直做比较重的数字转换

这些功能本身没有错，但放在同一拍里会让 Vivado 很难排时序。

## 我改了什么

核心思路还是一句话：

把“大块计算”拆成“小步计算”。

具体做了这些：

1. 硬降不再一拍算到底，而是一格一格往下走。
2. 消行不再一拍扫描完 20 行，而是一行一行检查。
3. 棋盘整理不再一次搬完，而是一行一行搬。
4. 碰撞检查改成按行看棋盘，少走很多绕路逻辑。
5. 分数显示先慢慢换算好，数码管只负责显示结果。
6. 最后又跑了一次更强的后路由优化，把很小的剩余负值补上。

这些改动对玩家看到的效果影响很小，因为多出来的只是几十个 100MHz 时钟周期，人眼基本感觉不到。

但对 FPGA 来说，每一拍要做的事情少了很多，所以时序容易过。

## 最终结果

最新后路由结果：

- `WNS = 0.076 ns`
- `TNS = 0.000 ns`
- `Failing Endpoints = 0`

bitstream 已经重新生成：

- `build/vivado/game_console_top.bit`

## 当前结论

slot2 已经并入项目。

当前工程能过 100MHz 时序，`WNS` 和 `TNS` 已经满足要求。

现在最慢的路径不在 slot2，而是在 slot3 里一个角色提示相关的判断路径。

## 这次综合失败是为什么

这次你在 Vivado 里点综合失败，主要不是代码文件真的丢了。

原因是：

项目里的 `slot2` 已经拆成了几个小文件，但 Vivado GUI 打开的旧工程只认识 `game_slot2_top.v`，没有把下面这些小文件加进去：

- `slot2_tick_gen.v`
- `slot2_input.v`
- `slot2_game_core.v`
- `slot2_renderer.v`

所以 Vivado 才会报“模块找不到”。

## 我修了什么

我加了一个同步脚本：

- `scripts/sync_vivado_project_sources.tcl`

它的作用很简单：

1. 把 `src` 里面所有游戏源码重新补进 Vivado 工程。
2. 让 GUI 工程也使用和命令行一样的优化设置。
3. 以后如果又新增了小模块，可以先跑这个脚本同步一下。

我还加了一个综合检查脚本：

- `scripts/check_project_synth.tcl`

它专门用来检查 GUI 工程里的 `Run Synthesis` 能不能过。

## 终极质检做了什么

这次按下面顺序检查：

1. 检查 slot2 的小模块有没有加入 Vivado 工程。
2. 检查顶层实例和模块文件能不能对上。
3. 跑 GUI 工程综合，确认不是只在命令行能过。
4. 跑完整 bitstream 构建。
5. 重新生成后路由时序报告。
6. 检查最终的 `WNS`、`TNS` 和失败端点。

## 质检结果

GUI 工程综合结果：

- `0 errors`
- `0 critical warnings`
- slot2 的 4 个小模块都已经被综合到工程里

完整构建结果：

- bitstream 生成成功
- 文件位置：`build/vivado/game_console_top.bit`

最终时序结果：

- `WNS = 0.076 ns`
- `TNS = 0.000 ns`
- `Failing Endpoints = 0`

## 当前结论

这次综合失败的问题已经修掉了。

现在 slot2、slot3、slot4 都已经在工程里，综合能过，bitstream 能生成，100MHz 时序也满足要求。

剩下唯一需要实物确认的是上板效果：菜单切换、VGA 画面、按键、蜂鸣器这些必须在 Nexys A7 板子上实际看一遍。
